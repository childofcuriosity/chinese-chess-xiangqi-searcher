第一步：把棋盘变成数据

char board[10][9];

struct Move {
    int r1, c1;  // 起点
    int r2, c2;  // 终点
};

大写表示红方，小写表示黑方，. 表示空位。局面还包括轮到谁走、将的位置与历史状态。

为什么这样表示？

  • 90 个格子，结构直观
  • 走法只需四个坐标
  • 适合快速走棋与悔棋
  • 便于增量维护分数和哈希

搜索会反复“走一步—看结果—退回来”数百万次。

数组适合快速修改与恢复。表示是否紧凑直接影响搜索速度。

第二步：教会电脑怎么走

几何规则

车走直线，士守九宫，相不过河，兵过河后才能横走。

阻挡规则

马检查蹩腿；相检查塞象眼。

吃子规则

炮吃子要隔一子，平移时不能隔子。

int gen_moves_for(int r, int c, Move* out);
int gen_all_moves(bool red_turn, bool only_captures, Move* out);

先快速生成“看起来能走”的伪合法着法。

挑马腿和炮架讲即可。only_captures 参数稍后会在静态搜索出现。

PST 直接记录“某种棋子在某个格子值多少分”。它同时表达棋子种类和所处位置。

代码中的兵 PST：过河后分值明显升高

这里要讲准确：当前 evaluate 的最终数值就是完整 PST，不是“基础价值加位置奖励”。初始化内部做过基准换算，但 get_piece_value 相加后正好还原 raw PST。

评分不是每次重算，而是随走棋更新

current_score -= get_piece_value(piece, 起点);
current_score -= get_piece_value(captured, 终点); // 如果吃子
current_score += get_piece_value(piece, 终点);
−

−

每步只改三个量，比每个搜索节点都扫描整个棋盘更快。

current_score 是增量维护的；撤销走法时做相反操作。

SEE：静态交换评估

在一个格子上轮流用最低价值攻击子吃回去，估计交换是否划算。

PVS + LMR

第一候选认真搜索；靠后的安静着法先浅搜，真有希望再完整重搜。

PIECE_VALUES 在这里很重要：SEE 需要比较交换中的棋子价值；它不是 evaluate 的独立评分项。
